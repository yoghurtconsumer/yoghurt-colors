## Implemented foundation

- Core: immutable settings/color/crosshair/display/profile/game/preset/capability,
  result and recovery models; typed effect commands/envelopes; service interfaces.
- Pure reducer: monotonic authoritative revision/generation, exact stale-command
  rejection, safety priority for shutdown/restore/suspend/disable/hold release,
  stacked suspension reasons, recovery blocking, foreground identity, desktop/game/
  manual profile precedence, temporary hold overlay, preview status contracts,
  and separately acknowledged observed state. Holds are never serialized into
  settings/profiles. Preset changes while held survive release.
- BackendPlanner: explicit global matrix versus per-monitor operations; no gamma
  substitution for saturation, no implicit native vibrance routing, no double
  software/native saturation pass, optional SDR gamma and selected-output
  vibrance, capture-route limitations and HDR/advanced-color refusal. Actual
  saturation/affine matrix, bounded tonal curves and baseline gamma composition
  are now implemented in pure Core; NVIDIA and CVD correction remain incomplete.
- Six bounded JSON Schema 2020-12 contracts: settings/profile/preset/ipc/remote/
  recovery. Embedded validator executes their used keyword subset. Strict known
  fields, enums, finite ranges, required fields, duplicate-key rejection, depth
  and size limits; typed validators add semantic relationships, portable assets,
  rational refresh, resource shapes and scopes.
- Atomic versioned JSON stores and settings/profile/preset repositories: exclusive
  write leases, same-directory temp, flush-to-disk, atomic replace, previous
  validated last-good backup, bounded reads, explicit errors. Corrupt primary
  loads last-good with warning and remains intact; saves refuse to rotate
  corruption into the backup. Recovery does not silently rewrite the primary.
- Explicit settings v0 -> v1 migration: `color` -> `globalColor`, `closeToTray`
  -> enum, preserved validated color/effects intentions, all new services off.
  No unsupported/future version guessing and no automatic file rewrite on load.
- IPC contracts: bounded little-endian frames, strict typed hello/command/result
  schemas, authoritative acknowledgment snapshot, revision/generation ordering,
  random per-session pipe name and 256-bit nonce, constant-time nonce comparison,
  one-shot authentication against injectable OS-derived peer identity. Required
  CurrentUserOnly options defined; default peer verifier/server fail closed.
- Recovery: owned-resource baseline/last-applied records, identity/generation,
  journal states and preview deadlines/statuses, atomic RecoveryJournal. No
  actual hardware snapshots or restoration are fabricated.
- WPF: eight navigation pages, Music panel, Default/Slate resources, DI container,
  keyboard/automation labels, capability diagnostics, distinct desired/completion
  status, saturation/brightness/contrast/warmth sample preview, draft reset,
  disabled Apply, settings persistence, default
  exit-and-request-restore, explicit opt-in tray with Show/Pause/Restore/Exit.
- Native/Overlay/Remote/Media providers return `NotImplemented`, including restore.
  No pipe or phone listener is started. Agent/Recovery executables and hardware
  harness exit with code 2 explaining what is missing. Test fakes are defined
  only in test projects and injected explicitly. No product fake-success route.

The complete Section 2 file tree is the final multi-stage target. Later-stage
math/interop/input/games/integration implementations, dialogs, image/scene
assets, packaging/CI and optional-cloud service trees are not represented by
empty source files. Their absence is intentional at this Stage 1 checkpoint.

## Launcher fix and continuing color-engine work

The user reported a console flash with no visible app. The old launcher used
`dotnet run` and checked only its exit code, not a rendered window. The precise
original Explorer-only failure could not be reproduced; a process handle alone
was insufficient evidence in earlier smoke checks. The new launcher removes
that silent-success path rather than attributing the report to an unverified cause.

- Run-Chromatic.cmd uses CRLF, an explicit Windows PowerShell host (including
  Sysnative for a 32-bit caller), preserves failure exit codes and pauses on error.
  .gitattributes and .editorconfig preserve its Windows line endings.
- Run-App.ps1 separates build and direct executable launch, chooses the first
  resolved SDK application, launches a normal window, waits for the application's
  first-render acknowledgment and verifies the child PID. A missing executable,
  startup failure, early exit or 30-second timeout reports a real failure.
- Use-DotNet.ps1 puts the local SDK first even if it already exists later in PATH
  behind .NET 8. This selection issue is covered by the launcher regression fixture.
- StartupDiagnostics writes atomic per-launch Ready/Failed reports, and startup
  exceptions are recorded with a local error dialog. Reports/build logs and
  latest-launch.log are under LOCALAPPDATA/ChromaticDesktop/logs. These are local
  development startup diagnostics, not a completed rotating crash-report system.
- `-SmokeTest` starts the real app with in-memory defaults, acknowledges the first
  visible rendered frame and requests ordinary window close; it does not load or
  modify the user's settings or enable any effect. `-NoBuild` is a developer option
  for already-built output. Automated tests suppress failure pause only in their
  child environment using CHROMATIC_LAUNCHER_NO_PAUSE.
- LauncherProcessTests invokes the actual .cmd through cmd.exe from an unrelated
  working directory. Its fixture copies build output into a repository path with
  spaces, with the legacy SDK first in child PATH. A second test checks missing
  executable failure, retained error text and nonzero exit. The .NET 8 historical
  probe explicitly excludes these actual-product launcher tests.

Continuing Stage 2 without enabling hardware writes:

- Matrix5x5: immutable row-major doubles, correct row-vector composition/fifth-row
  translation, no coefficient clipping, checked float conversion, preserved alpha.
- ColorMatrixBuilder: exact normative saturation 0–300%, brightness/contrast/warmth,
  software vibrance capped at 300%, distinct native-vibrance routing and explicitly
  named basic-lift approximation. CVD modes throw NotSupported until coefficients
  and attribution are checked; they are never replaced with a fake correction.
- ToneCurveBuilder: normal gamma, bounded shadow/highlight curves, temporary hold
  curve and optional gamma blend. GammaRampComposer samples the original captured
  monotone calibration per channel, applies warmth/tint after tones, and preserves
  exact 1536-byte baseline encoding. It never reads/writes a physical display.
- BackendPlanner uses software vibrance when native is unavailable, unselected,
  disabled or capture routing is chosen. Combining native DVC with independent
  extra saturation requires explicit advanced permission. No double vibrance pass.
- Display preview changes only fixed sample swatches, with one final pixel clamp;
  it is an affine illustration, not a capture or hardware parity claim. Reset
  returns all four draft controls to neutral. Desktop Apply stays disabled.
